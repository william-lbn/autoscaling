## 完整恢复边界

正式管理 `complete_service_reopen` 只接受完整原新开放摘要。原开放必须已确认且没有独立再关闭、没有资源 Active；随后重新认证 Root 完整原预算/出生/硬约束、资格、Runner 原 UID/实际容量、PG 有效有限期限与准确原开放 revision/容量/floor，最后检查同 Session 和 VM UID/RV。审计失败先独立再关闭，不将原开放改成失败或 NoEffect。完成写丢回复只读最近证据并重新认证，不产生新 setter 或新完成序列。

完成在一个 CAS 内保存完整原关闭/接续/rearm/开放、预算/首次未知/身份/HWM 的冻结上下文，撤销当前关闭门禁。当前关闭类别独立于外层格式，后继活动关闭仍按原 13～18 类别恢复，不将整个外层 21 误读成活动预算或失去跨容量约束。必填 safety_stage 固定 serving/closing，删除下一轮关闭不能投影为上一轮仍开放。

首次开放未知保留原 Phase、命令、owner 和空回执。独立 Covered 只保存严格更高、准确成功的原生开放及完成序列；普通 Begin、初始来源生产者、SDK 重建、初始 Outside/Host 读者据已验证覆盖接受后继业务，不重查或重发旧首次开放。正常预算完成仍通过原 Finalize/Cleanup CAS 原子替换当前永久头，完整旧恢复上下文继续保存；业务恢复本身不改预算，不产生连接排空、Host 释放或物理缩容许可。

重复周期只保留最近一份完整非递归上下文、直接前驱原生完成边界及累积证据摘要/计数。只有严格更高的准确关闭/开放、同 PG、非回退容量和序列才退休旧准入选择；资源在途未知不能进入本归档。原初始未知一直留在 InitialHeld，直到正常预算替换。旧 HWM 完整身份和结果过期水位不允许退回。开放前另检查原始上下文容量并留完整原生回执空间，压缩可存不代表后继证据可存。

Run 固定观察过期时已存在的账本水位。只有此后明确完成的新生命周期，再经完整当前来源/准确开放/有效期限和相同 RV 核验，才解除本地等待并恢复完整来源审计续租。仅 rearm、仅原生开放、当前布尔 open、旧完成或只读查询都不解除。完成 CAS 丢回复同样可按新持久证据恢复。
