# 首次 Host 预留等待与现有 SQL 服务解耦

本次只修复 PG 内存自动伸缩新增协调链。真实 Grow38:1 在预算 Prepare 完成后，精确 Host 来源 ConfigMap 尚未发布；Agent 把该等待当成 resource_unknown，Run 因错误跳过原完整审计续租，30 秒 Native 租约到期关闭准入。PG、normal 硬限与 VM 资源均未变化，不能计为 Grow 通过。

职责保持原架构：Scheduler 是 Host 预留的唯一写者，Agent 只消费确定名称和 UID 的原来源，Runner/Guest/PG 仍执行原合同。初次 GET 的 NotFound 仅表示尚未发布：Reader 附加 ErrHostNotPublished，保留 errors.Is(ErrUnknown) 兼容；Consumer 只将此精确情况返回 AwaitingFact,nil，使原 Run 继续完整旧预算、资格、Root、Runner、Native CAS 审计。该等待自身不续租、不写 Host、不推进资源动作。

第一次已固定 UID 后第二次 GET 丢失、来源被替换、Outside 丢失、Forbidden 及其他 Unknown 保持原错误。旧预算或硬限失效仍停止续租/关闭；不修改 Native 30 秒、安全证明、fencing、Unknown 或原请求期限，不重发已过期 Grow。接口中没有 PG 版本分支，PG18 复用相同上层语义。

验证：原生产两文件实测 RED，Host 等待时原 Run 续租为零；候选使用真实 Run、原领域执行器和明确测试 peer 的完整前驱，正常等待执行一次完整审计续租，且 Host/VM/Guest/PG 后续步骤均未 Start。Outside 丢失与其他 Unknown 均零续租；Reader 逐项区分首 GET 缺席、第二 GET 丢失、坏来源、Forbidden 和其他 Unknown。定向 2 根共 10 个 PASS，race/skip/OOM 为零。

相关发布/丢回复回归另跑：13 个既有子例通过；actual-scheduler-loop 旧夹具超时失败。精确旧生产两文件也在同一夹具同一断言失败，原退出码及额外诊断全部保留；没有为该旧夹具扩改生产，也没有声称整根全绿。组件通过不代替真实三节点内存端到端。
