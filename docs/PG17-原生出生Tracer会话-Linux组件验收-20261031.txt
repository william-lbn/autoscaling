二、会话与错误边界
私有 runNativeBirthTraceSession 接受已由 Root 原 pending 得到的 SOCK_SEQPACKET、
ProcessIdentity/PID-start/UID/GID、原可信 expected、原不可变 ELF FD/hash 和非 nil Persist。
不接受 HTTP 自选 PID，不把 native 帧的 SourceSHA 或请求 bool 当可信 builder。
原 SO_PEERPIDFD 必须实际可取；固定 /proc 目录及 start/exe/uid/gid/boot/单线程反复复核。
ELF 是原只读 mount 上的 regular FD，实际 hash 相符；环境只给 PATH/LANG/LC_ALL，
清空 LD_* 等，预期 BPF 由同原 ELF 的 root-only audit 命令编译，比较真实内核完整指令。

整个 ptrace 流程在专用 G 的非 TGID OS 线程上 LockOSThread：
SEIZE(options=0) → INTERRUPT/event stop → 原对象复核 → SETOPTIONS(EXITKILL) →
完整 base BPF → base Persist → 再核 → CONT0/ACK112 → 原生 self SIGSTOP delivery stop →
完整 final BPF/AS/R/198 已关闭 → final Persist → 再核 → DETACH0。
base/final 都不能绕过 Persist。final 状态是可恢复的待释放阶段，不可仅凭 fsync 回调或 ACK
将外部 ledger 晋级完整 Birth。回调 panic/Goexit 也是 Unknown，不吞成无效果。
final 停点真实 GETSIGINFO 必须是原 peer UID/PID 的 SI_TKILL SIGSTOP；其他同 UID 信号不算。

失败时未确认原对象只尝试保信号 detach，不设置 EXITKILL、不 numeric kill；
不确定时退役原 tracer 非 leader M，原线程目录真正消失后才返回。已确认对象才用原
pidfd SIGKILL，必须实际观察原退出；无法证明仍 Unknown，外层保留预算。
Go1.24.3 m0 特例不会退出，故 m0 只占位让第二 G 得到非 leader M，从不 SEIZE。
channel 收到结果不代表 M 已死；固定原 /proc/thread-self FD 观察目录消失才记退役。
官方准确 Go/Linux 源的 URL、SHA、行号及结论见 primary-semantics-source-lock.json，
实际工具镜像 /opt/go 源摘要与上述 Go source 相同。

三、独立审查发现及修复
旧版 Wait4(numeric PID) 默认可等待同 TGID 其他线程的 child；原退出被其他 reaper 收走后，
相同数字可能已属于新 child，存在误 reap 风险。旧 Host PASS 不覆盖此反例。
新版本三条等待路径统一 SYS_WAITID(P_PIDFD, 原 SO_PEERPIDFD,
WEXITED|WSTOPPED|WNOHANG|__WALL)，无 numeric fallback。
ECHILD/EINVAL/ENOSYS 保持 Unknown。amd64 siginfo 128B，准确解码 SIGCHLD、UID/PID、
CLD_EXITED/KILLED/DUMPED；CLD_TRAPPED 保留 SIGTRAP|(PTRACE_EVENT_STOP<<8) 高位，
不能截成 signal byte。WNOHANG 零事件单独处理。
独立 reviewer 核源码后关闭该代码阻断；真实验证另行执行，不以审阅代替 S。

四、实际验收
PG17-U-TRACER-001：禁网 race 模型，6 根/32 子场景、0 skip，package 1.065s。
含步骤故障顺序、取消同步 cleanup、tentative D/SETOPTIONS 边界、严格 maps/status、
Waitid 完整 event 解码与原 reaped 后数字复用不 fallback 的明确模型。
PG17-S-TRACER-001：真实 PG wire/ptrace 11 模式。valid 只有独立真实 base/final 核验和
两次 callback 后 detach；错 nonce/start/peer/ELF hash、两阶段持久故障/取消、
base callback panic/Goexit 都不晋级成功，实际 child Wait 结果必须核对。
PG17-S-TRACER-002：真实非 leader 线程退役两模式。tentative 无 EXITKILL 自动 detach，
PG 得不到 ACK 后退出；confirmed 已设置 EXITKILL 的原 PG 实际 SIGKILL，固定旧线程消失。
PG17-S-TRACER-003：真实同 TGID 不同线程 reaper 收走原 child 后，旧 pidfd ECHILD，
fresh child 自身 Wait 仍可成功。Host 不写任何 sysctl；仅独立369 Guest允许 ns_last_pid
强制复用，实际 oldPID=183=freshPID、otherReaperTID=181、parentTID=85，不能猜测通过。

Host：3 根/13 命名子场景，0 skip，真实运行 5.682s，见 host/result.json。
