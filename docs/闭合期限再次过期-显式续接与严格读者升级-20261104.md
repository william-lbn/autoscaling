# 闭合期限再次过期：显式续接与严格读者升级

本阶段为生产代码组件验证；未对当前 54e1 执行续接、重开、SQL 或内存动作。真实 K8s 恢复及四项内存核心验收仍待后继实际操作。

## 原问题与实现

服务保持 closed，第一次 Rearm 已有完整 retained 应用回执，却在 Reopen 前再次过期。原首次恢复拒绝已有 Rearm；旧关闭 continuation 只处理 pending；Reopen 要求 live lease；reopen 的期限恢复要求真实存在 Reopen/Closing。不能伪造这些字段或把旧快照当成 fresh。

新增显式内部动作 continue_service_rearm，只以最新 settled Rearm 命令摘要选择，不接收调用方 deadline 或自报 PG 事实。正式选主产生的当前 Owner 必须严格高于前驱和实际 lease epoch。先审原完整来源/实际预算，再复用正式 Native Fence（不续租）、fresh observe、同 UID/RV 确认，之后写前 CAS；发送前后仍审计全部来源。Native 的 higher-owner、原期限 CAS 和 TTL 均不改。

原 ServiceClosure.Rearm 全部原文保持。新增严格 protocol_version=1 的 rearm_continuation，保存最新完整选择和回执；第二轮起复用现有 ServiceReopenRetirement，保留完整直接前驱和累计证据摘要。前驱必须 settled，Unknown 不得被新选择退休。原 Active、首次开放 Unknown、实际预算全部不改。

重复旧 selector 不产生第二 CAS。普通轮询、observe/replay、回执预留和 Reopen 均选择最新 Rearm。Reopen 仍需 fresh live closed lease，最终完成仍走原生命周期归档。内部 Closing.Close 禁止嵌入新恢复字段，不能将已知字段置于另一域后被忽略。

## 兼容与部署

外层 v19/v20 的既有含义不变，新子记录有明确版本及 bounded strict/unknown-member/duplicate 检查。未含新字段的旧 JSON 重新编码逐字不变。旧严格读者必须拒绝新字段，未放宽 decoder 假兼容。

写新字段前，Agent、Runner、NeonVM Controller、Scheduler、Gateway、Adapter 六运行读者，以及 runtime-prepare、managed-route、qualifier 三操作 CLI 必须先升级依赖。不得对当前旧 Runner 提前写入新字段。Root 统一处理镜像、依赖、部署和必要正式保数据物理替换。

未增加 PG major 临时公共字段，沿统一版本化合同；PG17/PG18 内核、发行锁、Native TTL、Host 证明边界不变。
