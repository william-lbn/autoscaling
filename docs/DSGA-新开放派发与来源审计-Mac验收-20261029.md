# 新开放派发、完整来源审计与异常再关闭：Mac 阶段验收

日期：2026-10-29。正式 Run 串行管理入口已接通唯一新开放选择/派发、来源
前后审计、独立再关闭及更高 owner 的关闭接续。当前尚未解除业务门禁、完成
有界重复生命周期，不能将本批原生开放事实当成 PG17 全面完成；Goal active。

## 行为与不变量

管理入口只接收原关闭或原 WAL 的完整摘要，不接受外部预算、revision、期限或
回执。新选择依次核验原 Root 聚合/进程出生/完整永久预算/资格/Runner 发布与
当前原生期限，以同 VM UID/RV 写前 CAS 固定唯一请求；丢回复零派发。写前确认
后再次核验完整来源、有效期限、同 boot/floor/容量/准确准入边界及同 RV，失败
保留原 WAL 等待查询或原 owner 明确重放，不重选 revision。

原 setter 返回错误也可能已执行，因此发送后来源审计在网络错误分支之前。
来源/原生期限/VM RV 变化时，以最新原 VM、Session 和原生 fence/observe 选择
独立关闭，先持久确认再发出。关闭能处理未知或已确认开放，保留原开放相位和
旧关闭/首次未知/预算；不按当前 closed 补造 NoEffect，不释放或缩 VM。调用者
取消或失租不另起脱离 Session 的后台重试，原 PG 有限期限独立保护失联窗口。

普通 Run/Advance 和明确 observe 都只查询最新 WAL；未找到/较新/冲突保持未知。
新开放重放限原 owner 和完整摘要，仍须全来源审计；再关闭重放只发原 WAL，
来源损坏不妨碍独立关闭。更高 owner 必须显式选择最近关闭并写独立接续，不能
重发旧开放/旧关闭。原始/前驱/当前选择继续有界保留。网络不持本地互斥锁，
落账前复核 Session 和同 RV，Store/native 各自继续认证。旧关闭管理不能绕过新 WAL。

六个受信管理动作：`reopen_service`、`observe_service_reopen`、
`replay_service_reopen`、`close_service_reopen`、
`replay_service_reopen_closure`、`continue_service_reopen_closure`。
沿用现有严格管理和 PG wire，旧服务拒绝未知动作；本批没有另行发布产品版本。
新开放确认后外层关闭、Run 过期 latch、旧预算/未知仍保留，Begin/普通业务继续
拒绝；解除必须由后继当前许可/业务完成证明及生命周期归档共同决定。

## 失败保留与采用边界

首次默认沙箱拒绝 httptest 端口；已按用户授权使用本机网络验证。首个网络批
peer 返回 armed=true/deadline=0，终止失败批后修正有限期限，完整十八模式再跑。
接管 opening 例原先预设原请求已应用，普通只读先合法结清；改成真实未执行但
可能迟到的未知前提后定向通过。原批另四个接管成功子树仍采用。

十八模式原批 close-before 在 5 秒 Eventually 的后台条件中等待同步状态请求而
超时；同步请求受 Kube QPS/调度约束，不应由另一短计时器裁定它的成功。改为同
串行通道直接核实真实状态，close-before 26.35 秒、接管 close-after 10.14 秒通过，
生产条件未放宽。原批其余十七个完整成功子树采用，原整批仍明确为 fail。
新增取消独立22.85秒通过；误包含重复旧接续的辅助批已主动终止，不采用。
原 lint 字段/import 失败保留；最终修正后 lint0。所有采用测试进程均已终态。
