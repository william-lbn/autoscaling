# 未确认结算后的独立预算与服务恢复：Mac 阶段验收

日期：2026-10-30，Asia/Shanghai。本批关闭 R2 的类别15；此前13/14已归档。16～18以及R3～R8仍需业务代码与验证，PG17整体未完成，持续目标保持active。

## 问题和实现

全部资源前驱已经完整完成，但原 Finalize 尚未派发或其落账结果未知时，来源异常会独立关闭服务。此前即使来源恢复，也没有保持原未知事实的预算结算与业务恢复路径。现在明确的恢复管理动作先重新认证全部原 Prepare/Guest/VM/Host/Outside/Runner、Root约束、出生和PG终态，保存独立 `ServiceFinalization`，然后复用已有期限恢复、来源前后审计、独立开放和完整业务完成协议。

原 Active、Finalize 的 Planned/Unconfirmed、原命令、原请求issuer、旧永久预算始终保留。保存独立证明只有一次本地UID/RV CAS，没有外部资源写，不Start/Record原Finalize。原命令未知时逐字沿用完整原命令；未派发时新结算另存实际观察owner的SettlementEpoch。证明固定准确原关闭命令、确认序列、完整原操作摘要、三个完整资源前驱摘要、当前关闭Shared和预算来源，拒绝在途资源、取消及Cleanup混入此路径。保存前检查独立命令/回执的字节与JSON节点边界，开放前还预留完整原文及base64完成空间。

新开放经写前/写后来源认证、当前owner fence和完整原Key只读终态对账后，完成CAS才同时安装独立永久预算、撤销旧初始/实际容量预算、保存完整生命周期、完整原操作及独立覆盖终态、预算关闭水位，再清Active和关闭。永久预算使用独立RecoverFinalization步骤，原Finalize未知从不改为成功。原操作完整保留在永久预算中，结果缓存淘汰或后继服务周期不能丢弃；Source GC同时保留其中原payload及历史独立证明的来源。
