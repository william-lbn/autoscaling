# 首次预算合同与初始Host读取：阶段开发记录

源码`34814dfa08b84b1b9a6daa7c064f15cffd83f0f0`，沿用原Autoscaling功能
分支和冻结上游。**本阶段只有完整启动预算校验与真实来源读者，尚未接生产
首次预算持久化或开放准入，首次服务仍未完成。** 不改变既有VM v8/Node v7。

`budget.Initial`独立于Resize，固定原PG实例/初始容量、门禁初态、原root
bootstrap/出生、确切平台资格、原Runner/Pod/Node及初始Host数据。PG normal
与整个HugeTLB池只计一次；Shared只检查被该聚合容纳，不与聚合重复相加。
系统计费组已包含于系统外部承诺，不再额外叠加；系统/过渡/安全须独立且
完整。预算须不超过资格提供的可用Guest下界，不能借RSS/观测或错误的Host
声明补齐。所有关键边界、权限和未实现部分已在代码中用中文说明。

`MatchQualification`绑定原启动规格、root bootstrap摘要和原身份，不能按
未来目标比例推算启动值。`MatchCurrent`允许已认证floor和门禁状态前进，但
不允许替换原root、PG容量代次/前缀、启动成本或实际VM；未知分配不放行。
它本身不选服务状态，也不构造VM许可或原动作NoEffect。

`budgetclaims.ReadInitialPlacement/ReadInitialBudget`从固定客户端重读原
资格UID/摘要、Pod/Node和受保护的Node完整账本，直接消费QEMU启动前就持有的
原placement，拒绝持有缺失/不足、原UID被替换和Host资格变化。没有伪造一次
Grow成功或后续HostReservation。`RecheckInitialBudget`包围其他域请求；
Node其他VM活动可前进，但同VM的完整持有、原身份和资格须仍有效。
