## 行为与不变量

首次完整开放后，目标扩到1GiB的原VM命令可能在发送QMP前被不可重发取消，
实际仍是512MiB。恢复只可消费永久头中的完整原Initial资格，不能伪造一次
目标512MiB的Resize、Outside声明或VM完成回执，不能把原1GiB目标改小。

`ReconciledCapacity v2/InitialOutside`和普通Resize Outside互斥。生产读者
认证原资格UID/摘要、原Host峰值、原Runner/Node与实际容量；Cleanup Start
回复未知时继续持有Initial和峰值。只有完整实际预算Record的同一CAS才能
替换初始头。之后原Initial随CapacityHeld永久保存，当前预算读者持续核验
该资格，不能因历史淘汰或初始头已替换而改用同名/同数值来源。

原资格暂缺或进入释放时保持未知；恢复同一原来源后继续，不发现替代声明。
Host结清依据原Runner的不可重发取消回执及512MiB实际值，保留原目标与来源
审计，不把外层操作Finish或VM PATCH当作真实容量。下一次普通成功预算只能
通过完整Finalize原子替换实际预算。

资源发送分支原有两处局部`err`遮蔽使Apply失败变成零值Evidence预算错误。
出生查询和序列化改用独立错误变量，准确ClientError沿外层返回；原WAL/SDK
Pending、只读Observe恢复、不自动重发等不变量保持。

VM Model仍v9、Node仍v7、Runner record仍v2。旧读者必须拒绝不能理解的
实际预算v2；独立控制面之后移植时同步升级，不能为兼容放松来源校验。
