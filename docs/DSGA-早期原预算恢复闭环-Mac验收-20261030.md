# 早期原预算恢复闭环：Mac 阶段验收

本批接上一批关闭门禁/有界来源，补齐类别16最早期的完整业务：Prepare仍Planned或Unknown、其它资源步骤全部Planned且无Cleanup。支持原Initial、普通/独立Finalization及三种实际Capacity永久头，不把未派发资源动作改成成功。原Abort、Prepare Unknown、关闭命令及旧永久头的原始字节/落账序列保留。

## 持久与执行合同

`ServiceClosure.RetainedRecovery`保存准确原Source、旧关闭锚、原生Fence/Shared、Root、Runner的Completed/Cancelled/Initial来源及原取消见证。完成前逐轮重新认证；显式保存Proof、写前重开、查询、重开完成各自有UID/RV条件写。普通轮询只读，不创建恢复选择或新开放。

原关闭保持失败请求的目标BudgetID；新开放只使用认证旧预算ID及准确同容量代次。完整完成CAS才记录独立`RecoveredWithRetainedBudget`、退出Active并解除关闭。旧Initial没有Resize Request/Host Settlement；普通/实际预算只从原Anchor推进Through，未替换成新目标预算。

Model22的永久单槽`RetainedCoverage`保存完整原操作及独立覆盖，结果历史淘汰仍可审计原Unknown。连续恢复通过严格更高Key/revision/owner的有界Previous退休水位衔接；Lifecycle冻结上下文只保存旧槽摘要，避免递归复制旧证明。后继真实预算替换后旧槽仍为审计，不能授权当前来源或资源执行。新增字段/格式被旧严格读者拒绝。

来源复核同时核PG实际成本/有限准入选择、Root完整限额/出生、Runner不可变原回执与当前State、Outside/资格/Host/Pod/Node UID和真实VM读回。新Initial允许旧明确Completed/Cancelled原命令，绝不将它抹成无命令启动。普通取消尾保留两个不同原生意图和Witness，必须位于捕获的原Through之内。

GC持续扫描永久槽和原payload内引用，不因base64或历史淘汰漏保护。Initial独立只收已覆盖原请求留下的Outside：原资格/Birth/State和初始placement继续保留，不构造Host结清、不删Runner回执。分页/写次数有界；扫描完成后迟到CREATE仍会在新一轮发现。每次删除固定原UID/RV、正文SHA及原VM/Node/Lease边界。
