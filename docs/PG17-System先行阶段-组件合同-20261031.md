# PG17 System先行放置组件

本批只实现正式Bootstrap之前的System限额与用户任务放置。初次仅在原base-only Guest、
空PG/空System与完整固定ISO/Physical Origin来源下写原意图，fsync后施加原System cap、
先迁PID1再迁普通用户任务，实际回读后写完成。它不生成正式资源状态、PG出生或VM许可。
已有pending只允许明确原意图Replay，普通Prepare/Observe不隐式重放；异常原文件保留Unknown。
完成后的Observe不宣称持久同步，Prepare/Replay显式同步原文件。完整资源预算仍由原Bootstrap检查。

Linux上5根/25子项Go race单元通过；真实临时WAL的flock/fsync与并发、故障重放、来源漂移、
原文件损坏和完成后增长均有覆盖。kernel/ISO/namespace/ext4身份由明确模型提供，不能称真实Guest。
测试执行于原7ed9356加当时已修改源码；归档逐一核全部实际COPY Go/mod/sum与本批当前文件相同，
没有把当时dirty快照改写成一个纯提交。准确命令、稳定用例编号、源码与原日志哈希见同批validation.json。

当前只绑定旧normal-v1能力组件，尚未接sysinit/Runner，尚未采用后继PID-capped/normal-split。
后继双子域必须版本化PGEmpty/任务/leaf身份，不能继续以父procs为空判断PG未出生。
真实持久ext4、只读ISO、base-only放置、首次Movable增加及完整FS/I/VM来源分别验收；
首版实际normal安全下降与Linux/K8s全链仍是后续硬门槛，本批不解除任何生产拒绝。
