# Guest最大内存区域只读生产者与验证

新增四个guest_memory_maximum文件，统一PG版本无关的私有观察数据。固定真实proc/sysfs来源核准确369 release/notes、boot、唯一virtio18/virtio_mem driver、规范sysfs路径及原目录dev/inode；保留目录FD至读取后重核身份，前后读取完整iomem区域。不写online、设备、sysctl、WAL；不修改已有四构建身份或冻结组件。

`readGuestMemoryMaximumComponent`产出完整区域addr/length；`parseGuestMaximumIOMem`拒遮罩、嵌套、同名重复、第二个virtio资源、溢出和未对齐几何。普通online子资源可以改变。`match`核原设备/boot/build与区域漂移，不声称阻止未来特权写者。

`compareGuestMaximumGeometry`仅做私有算术一致性比较：实际QMP base+Guest区域==实际QMP machineMax，QMP设备addr/max必须一致，所有加法检查溢出。输入数字本身没有来源资格，当前没有生产跨包/原Runner发布协议。后继消费者必须核同原实例UUID/QMP真实几何、pc.ram/vmem0两backend、原Host预留与Guest原物理Origin；不得以Kpresent替代base上界。Guest没有独立block/node接口，结果明确NotIndependentlyObserved；本上界不靠它们获得更小数字。

准确内核源码和真实接口证据证明无需新kernel patch。Linux virtio_mem.c:2752缓存不可变几何，2796保留全region；kernel/resource.c:112仅对初始user namespace CAP_SYS_ADMIN输出真实地址。非特权遮罩会失败关闭。QEMU8.1.5 get_config和query-memory-devices同取后端MR大小，实际KVM独立交叉。精确官方URL、源SHA与行号说明见归档interface/interface-source-review.json。
