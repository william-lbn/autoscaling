## 实现与边界

retry_service_reopen 仅接受最近已完整确认再关闭的准确摘要，无 Active、同原 VM/PG、容量及预算。先审原 Root 完整约束/出生、预算来源、资格、Runner 身份和实际容量，再观察有效原生期限，最后同 UID/RV 写前 CAS 固定新选择；派发前后复用完整审计，异常独立再关闭。普通轮询不重新选择、不重发 setter；写前丢回复不发送，SDK 重建只读最近 WAL，显式原重放仍限原派发 owner 与摘要。

完整直接前驱包含原新开放的意图、未知或回执、Before、独立再关闭及接续；仅去掉更早 Retired，累积摘要/计数保留过去证据。因此空间不随故障轮数递归增长，24 次模型循环实际覆盖。只退休被准确更高原生关闭封住的准入选择，原首次开放未知、原预算及资源未知不改成成功或 NoEffect。原关闭类别和业务完成生命周期的外层职责仍独立，删除下一轮关闭不能投影成上一轮已开放。

新增可选字段由严格旧读者拒绝，旧零值记录编码不变；没有新增 SQL/Rust/PG HTTP 产品协议，也不交付中间产品版本。内部存储编号只约束兼容与完整证据保留。

## 自动链阻塞及修复

完整恢复后的自动 Grow 已完成，但新增完整前驱使同一未变账本在凭据检查中反复解压、严格解码和验证。实际诊断中，首样本约 1.85 秒，普通轮次 5.85～5.98 秒、续租轮次约 10 秒，超过配置的 5 秒采样间隔限制并持续重置缩容窗口。失败和总期限耗尽均保留，不采用为通过。

Store 只复用本 Store 逐字相同编码原文的完整确定性解码结果。每次仍发出 GET，检查本次 UID/RV、incarnation、bootstrap、Compute 和生命周期；Lease、Root、预算与 Runner 的当前来源照常重新读取。改变任何原文字节均重新严格解码，缺失/坏数据不复用旧模型；缓存只有一项，结果独立深拷贝，锁不跨网络或解码，并发旧解码完成最多替换性能缓存。公共 Inspect 继续独立严格解码。

修复后同一自动组合首样本约 51 毫秒、普通轮次约 0.39～0.45 秒，在原 5 秒界限内完成。真实生产者/Reader/Session/SDK/Store/Run/Runner/预算/Host 执行完整自动 Grow→Shrink，88.01 秒正常完成，最后正常 Finish 与 Host 结清；QMP peer 读回 1 GiB，扩缩各一次。PG/Root/Kube/QMP 是明确协议 peer，不能据此宣称 Linux 物理返还或性能认证。
