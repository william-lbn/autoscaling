# 原VM容量未改变时取消：Mac阶段验收

本阶段继续`codex/dsga-autoscaling-20261019`，不改变2026-10-26冻结的官方
基线。准确代码提交和源文件摘要见同名JSON收据；Neon只更新依赖锁和实施文档。

## 问题与实现

旧操作已完整成功并持有预算；新Grow的Host峰值和VM写前命令已落盘，但Runner
尚未发送QMP。此时取消不能把旧预算当成新目标成功，也不能仅凭VM的NoEffect
释放全部承诺：新的取消已经替换Runner的Last，原预算完成来源需要独立核验。

VM Model v7在首次Start撤销顶层BudgetBoundary的同一CAS中，保存原关闭链。
Begin但尚未派发的取消仍沿用原语义；旧数据不为升级补造来源。原链带预算Key、
Finalization摘要、记录/成功/Through序列，深拷贝并校验它严格早于本次操作。

新的联合只读者同时认证旧不可变Completed与新不可变cancelled_before_send，
要求同原Birth/State/VM/Pod/Node/PG身份、当前owner floor、无pending及实际
requested/actual均为原容量。两个来源各重读一次；普通CheckRetained仍要求
Last是原完成，不被放宽。封闭预算读取者在历史淘汰后仍核新取消Witness确实在
永久Through以内，不把取消转换为Completed。

恢复只接受严格的Grow结构：Prepare/Host完成，VM为带原生取消审计的NoEffect，
所有Guest/PG/Finalize/Resume均未派发。执行器再核旧完整预算、当前PG提交与
容量代次/成本、原Root聚合约束/出生、Host/Outside来源和原Node持有。缺一项
就保留在途承诺，不能仅按当前内存数字判断容量未变。

独立Cleanup记录旧Finalization和新取消审计摘要。当前准入已开放时只读确认；
当前关闭时，普通Advance返回可观察的等待状态，保持owner并等待独立可信选择，
不得覆盖暂停或运维关闭。`RecoverUnchangedAdmission`及对应循环通道只在可信
策略明确选择原Key后创建开放命令，使用旧预算ID/容量代次。命令未知时恢复
同一SDK pending，普通轮询只查询；显式重放仍核原派发者，不改epoch或目标。

Cleanup落账后再次核所有来源，下一轮才Finish。业务结果仍为AbortedAfterReconcile；
BudgetHeld原样保留，原关闭链延伸到取消Key。真实Host Publisher随后消费永久
Through，结清新峰值、防止迟到重占并清理失效Host来源。期间不重发PG/Guest/QMP。

没有跨域网络锁：来源读取不能成为缓存许可，最终落账依原VM UID/RV CAS；任何
读错、来源替换、未知写、失去owner均保留原事实，不清账后重试。它不覆盖PG/
Guest已经有部分效果或QMP可能发送的其他取消。

## Mac验证与兼容边界

[机器收据](DSGA-原容量取消恢复-Mac收据-20261027.json)保存实际用例映射、
原始日志摘要、代码摘要、初始失败和最终结论。
业务与模型用`-race -count=1`；只重跑新增/受影响路径，既有未变PG/Rust不重复。

- budget、journal、vmguard完整受影响包通过；覆盖必填/重复/未知字段、原链
  版本/摘要/序列、旧预算保留、接管、持久编解码及历史淘汰。
- 实际Session/Agent/Runner/Publisher组合先真实完成旧缩容与预算/开放，再新建
  Grow并执行原生未发送取消。普通已开放、关闭后显式恢复及来源/实际值漂移拒绝
  三类路径通过；不手填完整BudgetHeld或取消关闭链。
- 丢失Cleanup Start、setter执行前后、Record和Finish回复；重建生产worker恢复
  旧预算pending；普通not-found不重发。实际循环等待独立恢复选择并消费它。
- 原成功及取消历史由真实压缩注解字节压力淘汰；两个实际零派发取消后仍能联合
  认证旧完成/新取消，真实Host结清、迟到Reserve拒绝及Host CM GC继续成立。
- 复验受影响的旧完整容量取消与Host结清；无独立测试文件的admissionexec、
  budgetclaims、hostexec明确按包级无测试记录，真实调用由上述组合覆盖。
- 使用前一交付b9c284a1的完整源码快照：原v6读者接受v6、拒绝v7。新字段/版本
  不能由旧writer忽略后重写；升级需统一相关读写者。Node仍v6、Runner record
  仍v2，PG17 ABI不变，独立控制面仍冻结后续移植。
- 七包增量lint与vet通过。四个实际CLI的Linux amd64/arm64交叉编译及VCS SHA/
  ELF架构核验另见收据；它们只证明可编译，不是Linux二进制执行或内核验收。

保留初始失败：新代次Prepare夹具复用了仅支持旧代次的帮助函数；历史压力误用
原始JSON长度而非压缩注解预算；两段组合的固定Host Lease过期；未清除的空白/
错误Lease字段导致编译或lint失败。分别修正夹具、真实字节预算、同原Lease续租
及字段/格式。另发现实际循环把“等待可信恢复选择”当致命错误，已改为明确的
等待状态；没有因此自动开放、自动重发或放宽生产身份/来源检查。
