# 固定系统计费域与启动归组：Mac验收

日期：2026-10-26。沿既有 `codex/dsga-autoscaling-20261019` 分支。
本模块完成固定系统组这一预算组件；整体V3仍未完成，不能把它记为完整SystemOutsidePG或VM缩容许可。

## 行为与不变量

- 可信原计划显式提供 `system_memory_max_bytes`，0/缺省保持旧来源；封存Config的
  `system_cgroup`必须一致。不从RSS、百分比或开发机容量猜默认值。额度包含于
  `outside_upper_bytes`，只计一次；它不会增加PG聚合源。
- Linux只使用 `/sys/fs/cgroup/neon-system`，真实cgroup2/domain、同文件系统、
  root独占目录和迁移/限额文件。记录系统组device/inode，重建同名组不能收养旧身份。
- 先将完整原Bootstrap fsync，再在空系统组落实swap=0、memory.max，独立读回。
  PG组仍须为空；额度和启动归组分别记录。未持久确认归组不得出生PG或确认Held。
- 同一资源文件锁下先迁PID1，再有界扫描根组用户进程，排除PF_KTHREAD。未来普通
  子进程继承PID1的组；已fork子进程最多4轮归组，无法收敛即失败。数值PID迁移不是
  pidfd原子事务，前后starttime只能检出竞争；必须在sysinit、PG未出生、唯一root迁移者条件下运行。
- 部分迁移/读回/持久保存失败保留原意图及Unknown，阻止PG出生；重试同一范围。
  归组已确认后只读复核，漂移不自动回迁或修复，不杀进程、不冻结PID1。
- 运行命令、实际worker写前CAS、Quiesce、RootAggregate均保留原系统额度；
  内存命令不能变更/删除/新增该额度。核当前上限、占用、swap及PID1/根用户进程归组。
- `budget.SystemChargedFromView`只生产系统计费域组件，原Guest/Bootstrap来源持续冻结；
  PG正常限额、运行revision或owner变化不替换它。摘要不认证来源，必须经认证root读取/Match。

## 必须保留的架构边界

进程迁移不迁移既有memory charge；根组旧页、未计费内核项等仍需独立来源。
根组用户进程数量为0也不证明根组内存为0。新系统组不能单独成为完整SystemOutsidePG。
依据：[Linux6.12 cgroup v2 Memory Ownership及Organize Once and Control](https://docs.kernel.org/6.12/admin-guide/cgroup-v2.html#memory-ownership)。
启动期组额度太小可能导致管理服务OOM/启动失败，不是“安全完成缩容”。平台必须在
Linux资格验收中确定额度、活性余量及残余系统上界；本模块不补猜测值、不发VM许可。
V3完整Prepare/Finalize、安全降normal/私有后台上界、首次预算/开放、Host/QMP最终链、
公开worker完整生命周期及受控跨PG boot恢复仍需代码。

## 实际Mac验证

去重 **42顶层/70含子项，通过，0失败、0跳过**：

- resourceguard原包32/52，新补部分额度生效1/1，合计33/53。真实Mac文件锁/WAL/fsync；
  kernel和迁移是显式模型。覆盖额度先于归组、出生阻断、重新读盘、有限原值冻结、
  归组部分完成、读回失败、chmod造成最终保存失败（并非注入目录fsync故障）、原范围恢复、
  PID1优先、重复PID、有界不收敛、取消、stat解析、内核线程和0 tick PID1。
- budget7/7：系统计费域和PG聚合去重、持久来源、PG额度变化、漂移/缺字段拒绝，
  及持续Quiesce冻结系统额度。增加该断言后只替换1项，不叠加为第8项。
- 实际Session/双TLS客户端/VM UID-RV CAS的GuestReady新增4场景，1顶层/5含子项：
  显式额度、变更拒绝、写后丢回复重建worker只读恢复、归组漂移不确认。
- 改动前准确849d源码overlay1/5：旧格式可读，旧读者拒绝新额度/身份/Config。
  所有严格读者必须先升级，不能删字段、重造日志或把已启用来源降回旧模式。
- readonly Mac vet及Linux guard vet通过；真实root helper和Agent各amd64/arm64共4个
  Linux产物仅交叉编译。Agent新增预算文件后更新最终产物，不把重复编译计作额外测试。

复验命令（Mac，Go1.25.13，CGO/race使用Xcode SDK）：

```sh
go test -mod=readonly -race -count=1 ./pkg/dsga/resourceguard
go test -mod=readonly -race -count=1 ./pkg/dsga/budget -run '^Test(SystemCharged.*|RootAggregate.*|ContinuousQuiesceKeepsRetainedCostsAndRejectsUnprovedLowerLimit)$'
go test -mod=readonly -race -count=1 ./pkg/dsga/owner -run '^TestGuestReadyWorkerUsesOriginalBudgetAndActualDomainOrder/system-'
go vet -mod=readonly ./pkg/dsga/resourceguard ./pkg/dsga/budget ./pkg/dsga/resourceexec ./pkg/dsga/owner
```

执行配方、全部原始JSONL/stderr/编译日志位于工作区 `build/dsga-system-domain-*`；
准确源码、产物和日志SHA256见同名收据。不重跑未改PG/nativeHTTP/DSM/core225。
控制面需在本依赖推送核验后绑定准确版本并执行原Plan→Renderer→Runner新增合同。
