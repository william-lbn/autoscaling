# 结算未确认期间的异常关闭：Mac阶段验收

日期：2026-10-29，Darwin arm64。范围为全部资源前驱Completed、FinalizeBudget尚Planned或Unconfirmed、最后ResumeAdmission仍为空Planned的稳定边界。PG17整体尚未完成。准确源码摘要、采用子树及原始失败见同名Mac收据JSON。

## 业务问题与实现

Grow资源动作完成时，首次服务原准入仍可能开放。原实现只拒绝坏来源上的Finalize，且未生成新永久预算，安全检查因而跳过此窗口，已有准入继续开放。只读Go overlay采用原3c4e12b9的owner安全检查和PGWorker，新增planned生产组合在缺少关闭记录处真实失败。新增只读budgetexec审计仍供测试调用，因此不将该overlay称为整棵旧产品源码。

新增PendingFinalizationGenerationForClosure严格核验完整资源前驱、原结算阶段和空最终开放；expected+1必须不溢出。CheckBeforeFinalization复用正式结算执行器的Root/出生、PG、Runner、Host/Outside及资格审计，在Start/Record前返回，不改外层日志和预算。已持久的原Finalize未知按原命令逐字核验，不重算新命令。

异常后先原生Fenced，再从同boot、原操作允许的容量代次观察下一关闭revision；UID/RV写前CAS完整确认后才发送真实SetAdmission(false)。若来源在预审以后或真实Finalize Start之后漂移，同一Advance错误分支再次执行安全检查与独立关闭。健康的CAS丢回复保留原错误，不伪造关闭或结算成功。

关闭引用Active原目标承诺ID，只作为关闭上下文；旧InitialHeld/BudgetHeld/CapacityHeld保持原文，不把它们替换为尚未完成的新预算。保留全部Active、历史、原Finalize未知及Resize SDK未知；Resume仍为空Planned，不补造原开放、不Finish、不释放、不缩VM。来源恢复后保持关闭。

## 持久协议与恢复

Journal v15沿用独立ServiceClosure，Original为空、Reason为finalize_source_unconfirmed、OperationSHA256固定完整原Active。模型拒绝降版到v14/v13、抹Active/永久预算、错容量/旧预算ID、假原开放、前驱NoEffect及原结算改写。普通取消、完成落账和Finish均不能改写已冻结事实。

写前回复丢失不得派发；重建只查询原关闭；明确原摘要且原owner一致才允许原样重放。真实Lease失效后，更高owner先原生fence并持久接续选择，不覆盖原关闭/原未知。关闭成功、SDK再次重建及来源恢复都不能继续原Planned或自动重开。

旧读者必须拒绝v15，独立控制面后续移植须升级Journal读者，不能投影成完整成功预算。PG、Node、Runner及公开Request/Admission协议未变。
