# 早期关闭门禁与原预算来源：Mac 阶段验收

本批限定 PG17 内存自动伸缩已改写者及直接来源消费者；冻结基线不变。实际 PG17 仍为 `79367196a74eef82e67cac917877d2e6271d3e70`，未修改内核、Neon 扩展、管理 SQL 或 Router；复用此前准确源码的内核证据，本批不重跑未变的 PG/存储/HA 功能。

## 已收敛的代码边界

- Prepare 的普通 Advance、原重放及每次来源检查均先核原 VM 与独立关闭。旧 Snapshot 经 GET 发现关闭或 RV/owner 改变即拒绝。已经在网络中的 Outside CREATE 可能迟到提交；保留原保护对象及 Prepare Unknown，最终 Record UID/RV CAS 不得落账。不能把对象不存在、网络失败或关闭本身写成 NoEffect。
- Host 发布最终入口拒绝独立关闭；Scheduler 不再对已关闭操作发起新发布。Prepare 已 Completed 但 Host Planned 也可能有在途 Node.Reserve，因此新门禁不证明旧在途预留不存在。共用旧预算结清及 GC 的水位合同保持独立。
- 当前原预算来源导出为有界叶子：Initial、普通/独立 Finalization、三种 Capacity 头。保留原格式、摘要及首次落账序列，不递归复制旧 Model/Recovery/Lifecycle。Initial 不补造 Resize Request。独立 Finalize 允许原 Unknown 命令仍为零 SettlementEpoch；原 Planned 新命令另核新 owner。叶子自洽不足以认证原头，必须与当前完整 Model 精确比对。
- ServiceBudgetID 的永久头分支接统一来源 getter。类别 18 和类别 15 以后原 Active 的关闭 BudgetID 规则不变，不借旧预算 ID 改写已保存关闭。
- 在途旧预算 Read/Recheck 与空闲 ReadCurrent 分域。普通永久预算的空闲读者补齐 CheckClosedBudget；实际预算原有 CheckClosedCapacity 继续保留。在途复核只核原 BudgetBoundary 或 Start 同 CAS 捕获的 PriorBudgetBoundary 及来源 UID，不能授予全局结清或执行权。

## 本阶段不等于早期恢复完成

本批不新增 RetainedRecovery 持久证明、旧 BudgetID 重开或完成覆盖。早期类别 16 的完整业务恢复仍需代码：Prepare Planned/Unknown 且其他步骤全 Planned 的原预算认证、独立恢复落账、按原预算显式重开、原 Unknown 永久覆盖、完成 CAS、Host/GC/后继接线。Prepare Completed 而 Host 缺失须另核真实 Node 串行屏障，不能按 Host Planned 推断无预留。

P1 早期恢复、类别 18/后继消费者组合仍未全关；P2 私有/后台持续预算及安全降 normal、P3 直接服务接线、P4 准确 PG17 受影响最终组合仍需完成。当前粗估仍 38–76 有效小时，规划约 40–80 小时（5–10 个八小时工作日），P2 不确定性最大。

Linux/KVM/K8s/cgroup/HugeTLB/物理返还、Host 规模和性能 SLO 留目标环境单独验收。测试夹具、Mac 协议组合和实际 PG 内核证据分开记账。本轮不构建镜像、不部署、不合 main，不追冻结后上游；PG17 全面实现、Mac 验证和自有远程归档后才停止接续，不进入 PG18/PG16。
