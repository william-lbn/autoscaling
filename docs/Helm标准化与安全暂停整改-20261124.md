# Helm 标准化与安全暂停整改（首轮实测）

Root 资源读取未确认时关闭业务准入符合预算安全要求；不能把未知读当成可继续服务的事实。已确认安全关闭后的暂停，仍应允许受信任的控制面将同一实例排空、正常退役；直接修改关闭原因、清除永久预算或重新开放准入均不可接受。

本次增加共享的完整安全关闭识别与只读排空证明校验。要求原永久预算有效、关闭协议为10/11、idle_source_unconfirmed、已settled、无进行中事务、无重新开放/重置，保留准确关闭请求和原PG身份。Owner还必须取得当前runtime selection中同一暂停Operation的明确授权。此路径不授予重新开放、VM删除或Host预算归还权限；后两者仍由控制面和原Controller/Scheduler完成。

Qualifier只允许CREATE一次。只有原CREATE返回UID后，才在原总时限内使用SDK已有ResumeClaimUID进行有界只读确认；没有原UID、输入改变或来源漂移均不能按名字收养。API限流仍有限，未以无限QPS绕过一致性检查。
