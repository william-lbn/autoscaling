# 首次开放未知时的异常关闭：Mac阶段验收

日期：2026-10-29。范围为PG17首次开放未知的安全关闭；PG17整体尚未完成。
源码、逐用例、失败历史及本地日志SHA256见同名[机器收据](DSGA-首次未知异常关闭-Mac收据-20261029.json)。
收据中的日志相对工作区`build/`，不将夹具、只编译或历史失败写成产品通过。

## 原问题与修复

首次开放revision1已写入外层WAL但没有到达PG。来源异常后发关闭revision2，
原b078内核按连续revision规则拒绝；先补发开放1会在异常预算上开始服务。
同一新SQL回归及Rust原生SDK用例在b078真实失败，修复后准确二进制通过。

PG17提交`325aeb42a6080d86902d51892b2518a70ec2512b`只允许**关闭**单调提高
准入水位并跨过未投递revision；开放仍精确消费next。同revision完整上下文、
boot、issuer floor、容量及resize限制保留。所有判断和发布仍在原status_lock内，
无新增锁、分配或IO；最大uint64关闭不回绕，该boot耗尽后不能重新开放。
这是冻结自有b078之上的业务修复，官方冻结截止及清单不变，没有追入新上游。

## 持久业务与恢复不变量

Autoscaling Journal v12独立保存原首次开放Original、关闭Request及完整
ClosureReceipt。原InitialHeld、预算、写前序列和开放Unconfirmed逐字保留；
关闭仅证明更低水位的开放不能迟到生效，不证明原开放没执行、旧连接排空、
预算可释放或VM可缩。不能伪造首次开放Settled/NoEffect。

生产安全检查复用首次预算生产者的完整原Root、资格、Runner和PG来源核验。
来源异常时先原生Fenced，再核同boot/原容量/当前floor；关闭revision覆盖原开放
及PG水位，检查溢出后加一。原UID/RV写前CAS完整确认后才发送关闭；CAS丢回复
零票据、零派发。首次setter后、落账审计前发生来源漂移，同一Advance尝试关闭。

SDK重建恢复完整原开放、关闭及最新Continuation。普通轮询只查原完整选择；
原NotFound不自动重发。当前owner可显式重放原关闭；更高owner显式选择最新摘要
接续，原生fence后选`max(PG水位+1, 前驱关闭revision)`，避免原开放/关闭均未
投递时退到revision1。接续保持v12，原开放及原关闭未知不投影成完成。

完整关闭后重建不再恢复旧开放SDK pending，但外层原未知仍保留。服务仍关闭，
管理Begin及原首次重放受栅栏限制；来源恢复不自动重开。不释放预算、不缩VM。
旧v10/v11空闲关闭保持兼容；v12不能降版或删除原开放/完整关闭证明。

## 复现入口

Go使用现有离线依赖和Mac工具链；需本地监听权限的生产组合按平台审批执行：

```bash
GOPROXY=off GOSUMDB=off go test -race -count=1 ./pkg/dsga/journal \
  -run 'Test(InitialServiceClosure|ServiceClosure|ServiceContinuation)'
GOPROXY=off GOSUMDB=off go test -race -count=1 ./pkg/dsga/owner \
  -run 'TestProductionInitialUnknownSourceFailureClosesWithoutReopening'
```

真实PG验证需提供准确325a安装目录及配套Neon/test_dsg_region/neon_rmgr库，
`NEON_TEST_DSG_EXPECTED_SHA`设为上述完整325a，`NEON_TEST_PG_BIN`指其bin。
本地准确安装为`build/pg17-initial-close-exact-install`；完整构建命令及摘要
已列入收据，不能拿b078安装或其他PG大版本替代。SQL另提供
`NEON_TEST_DSG_LIBRARY`与`NEON_TEST_RMGR_LIBRARY`：

```bash
python3 -m unittest test_dsg_admission_closure test_dsg_admission -v
cargo test --locked --offline -p compute_api --features postgres-client \
  --test dsg_admission_continuation_native \
  closure_overtakes_unreceived_open_without_replaying_or_skipping_open_revisions \
  -- --include-ignored --exact --nocapture
```

SQL从Neon的ci目录运行，Rust从Neon根运行。CI严格门禁已加入新增SQL套件，
缺文件、零用例或skip仍失败。本次按受影响范围运行，未声称整个严格门禁全跑。
