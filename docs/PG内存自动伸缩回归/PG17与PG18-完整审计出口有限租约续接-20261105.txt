二、最小实现与统一架构
仍由原 Scheduler 管唯一 Host 预算、同一 Owner 串行协调、原 Runner/Root/PG
执行；没有新分配器、来源权威、Model 或 PG 大版本分支。
在原 Finalize/RetainedService 严格完整审计成功且 sameSnapshot 不变的出口，
以及 Grow VM 执行器原完整前审/完成回执后审的出口，同步续接原 Native 租约。
回调只消费本次审计，不缓存许可，不跨任何物理动作复用。随后仍 fresh Native
observe、完整 gate/容量/floor/期限相等、原 Session 及 VM UID/RV exact CAS。
VM 新出口还严格绑定原 PrepareCommand 和当前 RootAggregate 摘要，不能因
Root 身份看似相同而忽略硬限/Bootstrap/Birth/Held 漂移。摘要不含动态
GuestMemTotal/VM内存/RV，合法 VM7→8 不会被当成旧 Guest 值。
Unknown 不升级为完成；回调失败不 Start/Record；已过期不重置、不 rearm；
原恢复范围和旧无回调领域 API 保持。未配置资格的旧单步调用沿原 API；正式
Run 的原 Native 协议和 open Active 缺资格拒续门保持，不能视为生产降级许可。
Native30秒、单 PG 等待60秒、请求幂等键、预算保留与释放门均不变。
