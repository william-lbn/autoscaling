PG17/PG18共用Agent：业务审计与选主API有界隔离

问题与范围
本次直接服务于PG内存自动伸缩的多域预算审计与执行所有权。默认client-go每个typed客户端可能隐式使用5QPS/10burst；一轮完整来源审计可访问多个对象。现场正式部分效果恢复的立即Reopen请求实际耗时35.859秒，而原生安全期限为30秒。现场日志未记录限流等待时间，因此不能宣称默认限流是历史唯一原因。

实现与职责
仅正式Agent启用DSGA时，业务Kubernetes与NeonVM客户端共用同一个20QPS/40burst有限桶，避免各typed客户端分别建桶后隐含放大总配额。选主boundLease的GET/CREATE/UPDATE独立使用10QPS/20burst桶，经main、MainRunner、agentState、runDSGA完整注入。Session.Check、资格/Host来源审计继续使用业务客户端，其错误依然拒绝执行。
原owner.New保持同客户端兼容语义；新增NewWithElectionClient只分离吞吐。正式MainRunner启用DSGA但缺少独立选主客户端时明确拒绝启动。普通未启用DSGA的Agent保持原配置和默认行为。
Agent的boundLease本地循环没有Pod/Core读取；中央凭据服务的HTTP PodVerifier没有因本次修改隔离，不能扩大宣称。没有增加分配器，没有改变原Scheduler预算权威，也不改变Lease期限、UID/RV条件、隔离代次、WAL、来源证明或PG工作域真实硬限。

统一版本边界
此处只处理公共控制协议与API调用预算，不按PG17/PG18分支。PG主版本的差异仍由底层能力与适配层处理；Proxy与控制面不因本改动增加PG版本判断。
