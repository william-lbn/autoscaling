# DSGA 候选镜像发行合同

## 范围与触发

`.github/workflows/dockerhub.yml` 保留 `main` 自动构建，新增真实功能分支
`codex/dsga-autoscaling-20261019` 的 push 触发。独立运行负责 11 个 Autoscaling
构建及运行镜像；完整跨仓发行由 Neon 的 workflow 调用本 workflow，并最终发布配套
Neon/PG 镜像、版本清单与 Helm Chart。

调用方必须同时把 reusable workflow 的 `uses: ...@<40位SHA>` 与 `source_ref`
固定到本仓库同一提交。运行时拒绝分支名和缩写 SHA，checkout 后逐任务核对 HEAD。
不要让新 workflow 运行旧 `main` 源码；旧源码不具备本发行合同和资格发布器。

新 DSGA 版本为 `0.2.0-dsga.<run_id>.<run_attempt>.<arch>`，例如
`0.2.0-dsga.1234.2.amd64`。`main` 原日期版本格式保持兼容。不发布 `latest`、
`stable` 等移动别名。一次运行只构建一个原生架构，避免 amd64/arm64 覆写同一版本。
失败后使用 **Re-run all jobs**；单独重跑失败 job 会被 attempt 校验拒绝，
否则此前成功任务的 tag 和新 attempt 的 digest 可能被混装成“同一版本”。所有上传
artifact 名称也带 `-attempt<run_attempt>`，下载只匹配当前 attempt，完整重跑
不会撞 upload-artifact v4 的同名产物，也不会把旧 attempt 的收据重新混入。

需要的 Secrets 仍只有 `DOCKERHUB_USERNAME`、`DOCKERHUB_TOKEN`，沿用
`docker.io/williamluckyli`。由 Neon 调用时使用其 Secrets；不用跨仓 PAT。
public fork 的读取和 reusable workflow 不需要向其他仓库写入权限。

## 构建与依赖

1. 先运行发行脚本拒错测试及现有完整 Go race/envtest。
2. 构建 go-base 与默认 Guest kernel。
3. daemon 使用本次 go-base digest；单独完成后才编译 vm-builder。
4. runner 内嵌本次 kernel digest 指定镜像中的 `/vmlinuz`；vm-builder 的默认
   daemon 参数内嵌本次 daemon digest。其他组件按 `ci/distribution.json` 声明依赖。
5. 补齐 `dsga-platform-qualifier`。资格发布器保持 `--network=none` 编译，使用
   go-base 的依赖目录，不再被空的本机 BuildKit cache mount 遮蔽。
6. `verify-distribution` 拒绝缺失/重复镜像、混合 commit/架构/版本/attempt、
   非本 registry、缺失依赖和与本次发行不符的依赖 digest。

镜像数量为 11：go-base、vm-kernel、daemon、controller、vxlan-controller、runner、
scheduler、agent、cluster-autoscaler、vm-builder、dsga-platform-qualifier。
每条现有 `kind=runtime` JSON 记录保留 name/image/digest/source 字段，并新增
`architecture`、`execution` 与 `dependencies`。

## 机器可核验的能力边界

`autoscaling-capabilities-attempt<run_attempt>` artifact 中的 `autoscaling-capabilities.json` 与
11 条 image record 在同一运行中生成。文件包含：

- 同一源码 SHA、版本、架构、GitHub run/attempt 和全部镜像 digest；
- `release_channel=candidate`、`normal_qualification=false`、
  `production_ready=false`、`latest_eligible=false`；
- 实际默认内核的 release、镜像 digest、vmlinuz/config/notes SHA256、输入配置
  SHA256及源码 patch 清单；
- 历史已审 normal-split-metadata-v1 五元组，放在独立的
  `expected_audited_identity` 字段；
- `vm_builder_default_system_mode=legacy` 与待完成 normal 发行条件。

kernel job 从本次已推送的**镜像 digest** 拉取 `/vmlinuz`、实际 resolved `.config`、
ELF `.notes` 与 `kernel.release`，连同与 image digest、source、run 绑定的 JSON
上传 `autoscaling-kernel-receipt-attempt<run_attempt>` artifact。汇总重新计算文件 hash 并校验绑定。
输入 `.config` 与实际 resolved `.config` 两者分别记录，不能混为同一个 hash。

### 为什么不能直接把新镜像称为 normal 真缩容发行

本 workflow 默认 Guest kernel 使用根目录配置及公共 0001–0007 patches。
它未启用 normal strict page counter，也未应用 profile 内私有 0008 metadata guard。
`vm-builder` 未指定 `--system-mode` 时仍默认 `legacy`。
包含最新 DSGA 源码、通过普通镜像构建，并不构成新 VM 的 normal 出生/预算资格。

运行时代码 `pkg/dsga/resourceguard/physical_kernel_build.go` 只认可已审精确五元组。
当前 normal-split-metadata-v1 是：

| 字段 | 已审身份 |
| --- | --- |
| profile | `neon-linux-6.12.26-dsga-normal-split-metadata-v1` |
| release | `6.12.26-william-normal-split-metadata-v1-c67181104ec1` |
| vmlinuz SHA256 | `18c9fd3a38bbe5a087b98998c856898e97ee3f0bc68681b13f0287912849e1ad` |
| resolved config SHA256 | `966e615127358d6d0dcf4f6ca884a07702e957ad07a95909cf95feca4aae5441` |
| notes SHA256 | `a496a3c44fc0b374f100ba0331a2e21f02d6e79ac999769a8d3ad4d71b76024e` |

历史 `neonvm-kernel/profiles/normal-split-metadata-v1/build.py` 使用原本机 `neon-data`
builder、资源约束和构建上下文；不能假设 GitHub runner 重编即可得到同一个 `.notes`
及二进制。也不能由流水线生成新 hash 自动改运行时白名单。

完整 normal 发行后续必须提供可拉取并验证上述三 hash 的原内核制品，或对新的精确
内核重新进行独立验收；随后接入 normal-split-v3 build plan、原 ordinary package
lock、各 PG ELF digest、新实例 bootstrap/qualification 和对应真实 KVM/Helm 验收。
历史测试日志不是这些发行输入的替代品。

## 验证命令

### 默认 Linux suite 的真实执行环境

首个功能分支云端 run `42454897452` 暴露：GitHub runner 的 UID1001 无法创建或
破坏 root-owned 的 WAL/ISO/镜像输入正反例；只读 Source reader 的输入也没有物化。
这属于真实环境合同缺失，不能靠放宽 owner、inode、只读或准入检查消除。

`ci/test.sh` 为八个 root 分片生成独立测试镜像，沿用 `versions.env` 的 Ubuntu 原生架构
digest。它仅增加 CHOWN、
DAC_OVERRIDE、FOWNER 三项能力，不使用 privileged、宿主 PID/网络或 Docker socket。
默认 seccomp、no-new-privileges 与网络隔离保留；协议测试的 HTTP/UDS 使用容器本机。
源码、Go SDK、envtest 二进制只读；临时文件和两个 Go 专用缓存可写。
缓存结束后归还 runner uid/gid。独立 `actions/cache/save` 在测试失败后仍执行，
仅保存 Go 编译缓存和下载的依赖源码，不保存测试证据、结果目录或凭据。缓存键包含
原生 OS/架构、精确 Go 版本、模块摘要、源码 SHA、执行环境及调用仓库/ref 摘要；
PR、分支及跨仓调用方隔离。同一 ref 可恢复此前源码的编译缓存，Go 按实际源码
重新校验输入；`-count=1` 仍要求每次实际执行所有被选测试。

第二轮云端 run `42458781962` 的完整日志证明 Azure 测试需要宿主 Docker daemon，
而 controllers/envtest 的 apiserver 在隔离环境中启动失败。两者现在由
`ci/test-integration.sh` 在独立普通 runner 任务中完整执行：只选择 `pkg/reporting`
与 `pkg/neonvm/controllers/functests` 两个**整包**，没有 `-short` 或测试名过滤。
这个任务仍使用相同源码、Go toolchain、race、30m 上限及完整实时 inventory，
开启 apiserver/etcd 原始输出；Docker socket 不进入 root 容器。

Azure emulator 保留 3.30.0，并固定其公开多架构 manifest digest：
`sha256:01233a6593e2f2cb3e515731f83ca720454018b80e08207f18fa691b71bd054d`。
此摘要已与 [MCR 返回的原始清单](https://mcr.microsoft.com/v2/azure-storage/azurite/manifests/3.30.0)
逐字 SHA256 核对，包含 Linux amd64/arm64。每个子测试结束清理自己的 emulator
容器。envtest 使用原仓库对应的 Kubernetes 1.31.0 及固定 setup-envtest 提交。

`ci/test-fixtures` 通过当前源码固定 v3 生成器生成 `/etc/inittab`，另生成小文件、
非 ELF 文件及两个 128MiB 文件；每个长度和 SHA256 都从实际文件读取。Docker COPY
提供 root owner，容器只读根使它们全部父目录实际只读。此 fixture 仅验证文件 reader
的顺序、hash、并发与取消合同，**不授予 Source、normal 或物理缩容资格**。

测试保留全部默认包、`-race -count=1 -p 2`，包/片总预算为 30m，各用例原有 deadline
不变；每片 workflow job 总预算 90m。首次失败中 journal 在第 114 个顶层、owner
在第 19 个顶层触发原整包 10m 超时，因此不能只扩大一个未经测量的整包期限。
root 矩阵固定八片，另有第九个宿主集成任务；每个任务用当前平台真实
`go list` / `go test -json -list` 枚举所有默认
`Test`、`Example`、`Fuzz`（包含默认 fuzz seed 回归）。owner/journal 按
`SHA256(package + "/" + topLevelName) % 8` 分配整个顶层，其全部子测试随父执行；
两个宿主集成包只在第 8 号任务完整执行，其他包只在第零片完整执行。
没有删除测试或新增 skip。schema 2 收据记录 `root_shard_count=8`、`shard_count=9`、
`execution_environment` 和实际 uid/gid。独立 `test-coverage` job 同时依赖八片及宿主
任务，核实九份身份/inventory 一致、指定执行环境与用户正确、两包没有在 root 片
重复或遗漏、选择互斥且完整、所选测试真实出现并终态成功；原有条件
skip 必须附明确理由并单独记录。只有此门禁成功，go-base/kernel 才允许构建。

未开启要求独立已审 Guest/KVM 输入的 `dsga_native_*` build tags。后者仍是独立
物理验收，不能用此 suite 冒充完成。每片（包括失败）上传
`autoscaling-tests-<arch>-shard<0..8>-attempt<attempt>`：完整 Go JSON 事件/标准错误、
完整 inventory、本片 selection、执行环境、源码与退出状态；root 片另含镜像构建
日志和真实 fixture 清单，宿主片含 Docker/envtest 实际输出。
聚合产物为 `autoscaling-test-coverage-<arch>-attempt<attempt>`，包括明确 skip 清单。
失败会阻止全部镜像构建，`status.json` 保留 `normal_qualification=false`。
