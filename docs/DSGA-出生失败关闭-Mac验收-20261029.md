# 原Runner出生失败的不可撤销关闭与Mac验证

日期：2026-10-29。基线AS `a29c79f825732352e4aac04d2974d28feb5a016b`。
准确七份Go源码和完整日志摘要见[机器收据](DSGA-出生失败关闭-Mac收据-20261029.json)。

## 问题和实现

原Initialize已fsync出生nonce、但State/Binding的CREATE或读回失败时，调用方没有
Runner可用于CloseUnlaunched，初始Pod成本无法沿正式来源结清。现在同一次调用
返回错误之前，先持原目录flock封存birth-abort永久屏障，再用独立10秒期限补齐
原nonce、原文和已确认UID。补齐成功仍返回nil/error，不能转换成启动QEMU。

原State UID一经确认便独立fsync，之后才能创建Binding；Binding确认后将两者
一起fsync，再保存仅供关闭的pristine WAL。再次失败/重建只能读取原检查点，
已知来源缺失或同名换UID都拒绝，不重生nonce、不覆盖坏WAL、不收养旧运行实例。
Engine持同一flock先核失败屏障；Tick和RunQEMU返回ErrStopped。唯一允许的
关闭接续生成现有ProcessExit v3：没有launch、PID或Wait，不触碰QMP/Start。
先本地持久屏障，再发布原不可变退出来源，关闭不修改VM外层意图/预算。

Scheduler复用原v3消费链：同Pod UID/原ContainerID、全部容器终态、原Node域及
UID/RV CAS缺一不可。sidecar仍运行时保留全部成本；Node回复丢失保持Pod保护，
重读结清后先写VM退休锚点，再移除保护。重复消费不重复归还。旧未知版本断言
同步修正为v9，因为Node v8已有原初始容量语义；生产协议未放宽。
