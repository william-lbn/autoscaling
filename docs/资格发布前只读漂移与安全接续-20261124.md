# 资格发布前只读漂移与安全接续

第三轮全新安装后，PG17在node3的VM已Running，原Operation在资格发布阶段失败。原Job只输出publication/unconfirmed；当前未发现资格CM，也没有原CREATE UID的写后未确认记录。原错误正文未保留，不能据此断言具体失败就是来源漂移。失败项目经公开删除Operation正常退役，VM/Runner和Host持有均结清，原失败证据保留。

审查发现另一个明确活性问题：SDK在CREATE前连续核对完整来源，两个只读快照不同会返回普通错误；自动CLI未区分这个已证明零写入的阶段，直接终止。新增具名ErrSourcesChangedBeforePublication，仅该分支允许在原总期限内重读同一报告。认证、完整来源、原身份和所有硬预算约束不变，不重新采集、不换报告。其他普通错误继续拒绝。

CREATE未知结果仍是Unconfirmed；没有原返回UID绝不自动重放或按名字收养。已知原UID只允许ResumeClaimUID只读确认，原报告/SHA和原对象不可替换。任何错误中嵌套Unconfirmed都优先保留该边界，即使内部包含发布前错误也不能重试CREATE。发布前日志增加固定白名单诊断码，不记录Kube/Root错误正文、URL、报告或凭据。

验证：Qualifier CLI与SDK共72项通过，无失败无跳过；新增SDK真实零CREATE断言、纯读取漂移接续、未知CREATE嵌套原因不得重放、取消期限不得延长。该记录不替代后续228真实业务复验，最终结果以Helm标准化最终验收归档为准。首次Root HTTP异常和这次第三轮原始失败的细分根因仍需完整证据，不以推测填补。

本次只构建Qualifier，其他已实测Agent/CP/Gateway/Guest保持各自明确摘要；Host停域工具和CP使用的SDK仍显式固定3567，未冒称所有镜像均来自本次提交。完整组合源码/镜像对齐仍按用户要求后续处理。
