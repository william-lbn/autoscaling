# 资源完整结算后的服务恢复：Mac 阶段验收

日期：2026-10-30，Asia/Shanghai。本批只关闭 R2 的类别13/14；类别15～18及R3～R8仍需代码和验证，PG17整体未完成，持续目标保持active。

## 问题和实现

所有 Prepare、Host、Guest、VM、PG 资源效果及 Finalize 已完整落账后，原最后 Resume 可能未派发、回复未知或已完成；来源异常已被独立关闭。此前恢复仅支持没有 Active 的边界，无法恢复这些已具备完整资源预算的操作。现在在完整来源恢复并审计后，可以选择更高原生 revision 的独立开放，再明确完成业务恢复。

原 Active、原 Resume 的 Planned/Unconfirmed/Settled、原完整预算和原请求高水位，在完成 CAS 前始终逐字冻结。完成 CAS 同时保存完整服务生命周期上下文、原操作与独立 `CommittedServiceCoverage`，产生 `recovered_after_resource_commit` 终态、永久预算关闭水位，最后撤销 Active 和当前关闭。它不宣称原 Resume 成功，也不直接授予 VM 或 Host 释放许可。后继正常缩容和 Host 结清仍走各自生产协议。

恢复选择、原生期限恢复、再关闭后重试及重复过期恢复均严格接受完整资源结算的类别13/14；Finalize未完成、PG/Guest/VM在途或取消清理的15～18继续拒绝套用此路径。带Active的恢复摘要固定完整原操作；没有Active的已有摘要字节形状保持不变。写前按原始JSON及base64膨胀预留完整完成证据，不以压缩率或截断未知换取开放。

SDK重建会恢复已落账 Resize 的本地 pending。新增只读终态对账：先认证全部原来源，再以当前owner fence隔离旧写者，通过完整原Key查询并匹配原终态，只解除相同SDK pending。缺失、矛盾、并发均保持原栅栏，不Advance、不Resize、不改原WAL或预算。更高owner完成先前已确认开放时，原开放issuer保持不变，当前有限期限和floor必须属于完成owner。

## 实际验证

Mac race按package/test去重采用189个顶层、884条含父子/种子记录，0fail/skip；其中种子不代表持续fuzz或独立E2E次数。Journal完整包631.127秒，PG执行器42.488秒、预算来源2.338秒、Host约束26.155秒、Host执行器2.542秒均通过。采用日志、命令、源文件SHA256及逐项测试见同目录机器收据。各采用批次均要求整包通过、0fail/skip；互补定向运行按package/test去重，不用部分父根耗时冒充整个矩阵。

- 生产恢复覆盖原开放未送达、已应用、已落账、原Resume未派发、完成CAS丢回复，以及已确认开放但完成前真实Elector失租接管。
- 八个故障窗口：写前CAS丢回复、setter发送前/后、回执落账丢回复、选择后来源漂移、未知setter后来源漂移、原PG终态查询不可达和终态冲突；SDK重建及普通观察零新增setter。
- 原生期限过期后真实Elector接管、rearm、同容量重试和完成；模型覆盖三种原Resume状态、三轮更高owner重复过期、后继三轮生命周期、19次零派发取消与历史淘汰。
- 原操作/覆盖/预算水位删除与投影拒绝、严格必填/重复/未知字段、原始恢复空间写前拒绝、完成CAS原子性、缓存返回值16并发隔离通过。
- 恢复后自动Grow→Shrink组合120.71秒通过，正常Finish/Host结清，QMP peer最终1GiB，扩缩各一次。
- Journal、PG执行器、预算来源、Host约束及Host执行器执行race回归；旧恢复入口六子项、完成前接管及模型补充定向回归通过。三包vet、最终增量lint 0 issues，33个消费者仅编译通过，diff检查通过。

首次模型夹具缺ExpectedCapacityGeneration、首次生产peer的armed/deadline不一致、真实SDK pending阻止恢复、静态检查、接管peer把查询epoch误作实际lease floor，以及lint默认cache越出沙箱的失败日志均保留，原因和修复见机器收据。接管peer修正后完整场景通过；生产lease校验未放宽。失败批次不涂绿，也不作为成功批次计数。
