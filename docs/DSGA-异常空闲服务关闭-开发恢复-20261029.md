## 本批代码与合同

此前异常采样只冻结新建议，部分错误会让 owner 退出，不能视为已经关闭服务。
新增生产 worker 空闲边界检查：Root 原日志及已确认约束、原出生、永久预算的原
聚合 SourceID 与 Guest 最低保证、原资格/Host/Outside/Runner 来源。坏来源只有在
**没有 Active、首次开放已落账、原 SDK 无未知**时进入本批独立关闭；合法伸缩中间态
不从这里判错。没有把无法实现的在途关闭或坏外层日志关闭归为待 Linux。

`ServiceClosure` 将同一 PG/owner、原预算 ID、完整关闭命令及摘要、写前序列和
实际原生回执持久保留。首次写前 UID/RV CAS 完整确认后才向原 Compute SDK 发送；
CAS 丢回复零 setter。PG 关闭前/后丢回复时保留同一未知，重建从原 WAL 恢复，普通
轮询只查询。NotFound 不表示 NoEffect；只允许原派发 owner 明确选择原命令摘要重放。
新管理选择为 `replay_service_closure`，不允许提供新预算、代次、目标或原生 body。

日志首次使用升级 v10，旧读者拒绝；禁止删字段/降版本来回滚。已有 v3 无 Runner
预算不能投影成 v10，继续保持原等待；生产当前采用完整 Runner 来源。关闭记录
阻止新 Begin 和管理开放/恢复接口，保留全部预算、历史及旧连接，不释放 Host/
Outside、不能据此缩 VM，也不声称已有连接排空。来源恢复不自动重开，受控重开
协议仍是后续代码。所有 AS 消费者需要同一发布版本；整体能力继续默认关闭。
