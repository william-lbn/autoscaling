# PG17 原生准入失联关闭与生产续租：Mac 阶段验收

更新：2026-10-29，Asia/Shanghai。PG17 内核提交 `33c92fe33e741309f9e8ab23e3767fb6f2210216` 已推自有原功能分支并核完整远程 SHA。本模块解决管理链/WAL 失效后旧开放可能无限保持的问题；整体 PG17 尚未完成，不作为生产发布认证。

## 行为与不变量

受管 PG 的首次 issuer Fence 启动单调时钟期限（默认 30 秒，启动时固定 1 至 60 秒）。后台独立关闭过期准入，连接、事务和消息入口也检查期限，不要求管理器能读取或修复旧 WAL。正常工作不会因单次失败被伪造为已完成；原预算、在途动作及未知事实均保留。原生关闭不等于排空，更不是缩 VM/释放预算的证明。

续租严格 CAS 同一 boot、owner floor、容量代次、准入 revision 及原 deadline。查询、重放、乱序、提高 floor 和迟到普通续租均不能延长已过期授权。更高 owner 的显式 rearm 只恢复期限，准入继续关闭；受控重新开放仍须完整原预算恢复流程，本批没有把底层 rearm 当成该业务已经交付。

Neon 扩展 1.16 正式 SQL 入口及可逆升级/降级均已实现；撤回 SQL 不撤回内核过期水位。Rust SDK/认证 Router/Go SDK 固定原实例与 owner，拒绝重复、未知及不完整字段，且不清任何伸缩或准入 Pending。接口版本数字是序列化合同，不表示交付中间产品；整体仍按 V3 架构实现完整 PG17 内存自动扩缩容。

生产 PGWorker.Run 在新派发前强制协商原生期限，旧网关不能降级为无限期服务。只有完全未派发、无历史/预算的本地取消允许零 PG 访问。续租在原串行 goroutine 内先核 Session、完整来源和原 VM UID/RV，再做 deadline CAS；失败停止续租，不发盲心跳、不自动 rearm。每期限三分之一审计一次，避免每轮重复全来源网络读取挤占策略采样；既有业务动作的写前审计不变。
