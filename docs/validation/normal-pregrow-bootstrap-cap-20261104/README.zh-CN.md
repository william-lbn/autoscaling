# PG17 首次扩容保留出生数组硬额度

真实 Compute 出生时数组域 A 的 memory.max 为 256MiB，当前四数组实际合计约 2MiB。扩容至 8192 个 buffer 的数组及原 helper 预留仍可落在原 A 中。旧实现按实际需求算出低于出生 cap 的 A，并在 N 增长时强制要求 A 严格增长，使合法扩容在写前失败。

本次修复在原资源锁、相同 PG pin、四数组映射及可信 policy 校验后，将 pre-grow 的数组目标取为原需求计算结果与本事务原始 A cap 的较大者。每次 fresh check 使用同一个原始快照。N 增长时允许保留 A；A 不得降低。N 下降时仍必须降低实际 A，并保留完整四数组释放证明、P+A+F+I 覆盖、真实硬限写入/读回、租约和 Unknown 门禁。公共 DTO、PG17/PG18 内核引用及自动策略不变。

验证仅覆盖这次修改：旧源码的确定性反例真实失败，修复后准确三个根以 race 模式通过，零 skip；N 下降但 A 相等的负例明确先满足覆盖再断言方向拒绝。第一轮 GREEN 的新增夹具错误把切片零值当作四数组，在调用生产函数前 panic；原失败与日志保留，修正为显式四数组及深拷贝后完整重跑三根。没有把该失败算作通过，也没有重跑无关上游测试。

随后使用同一冻结源码构建静态 resource-guard 和带原六个发行参数的 Builder。实际 SDK 为 3 CPU、3GiB、无 swap，峰值及 OOM 指标见 receipt.json；缓存、旧镜像和原失败目录保留。本收据不代表新 Guest 已部署，也不代表 Grow、安全 normal Shrink、Regrow、自动策略或生产验收已通过。
