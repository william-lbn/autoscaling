# 正式 PG Owner 只读资源检查的有界公平调度

现场资格采集在 90 秒超时。对同一实际 Agent 的一次 20 秒只读请求和已有 pprof 采样显示，请求一直等待进入原控制队列，Owner 正在串行执行持续安全审计；不能把它误判为 Guest 拒绝来源，也不能根据这些采样指定原采集中某一次 Read 的唯一耗时。

只把正式 PG endpoint 的 resource_state 请求送入容量为 1 的私有只读队列。一次完整审计及原到期续租成功后最多发放一次读取额度，在下一周期审计前优先处理已经排队的读取；额度用完必须再经过完整周期。原执行器仍串行，写命令、恢复 endpoint、租约/身份/来源检查、调用取消及 Unknown 处理均保持。连续读取不能无限推迟安全审计或续租。

确定性回归通过私有、生产默认 nil 的测试屏障固定排队顺序。RED 是原调度次序加等价只读队列和测试屏障，并非未修改旧 ELF；GREEN 只增加一次读取额度优先点。四根覆盖读取先于下一审计、读取洪流仍保留审计/续租、取消/租约/新鲜来源失败拒绝，以及写命令和恢复队列不分流。race 模式四根/七个通过事件，零 skip。首次工具任务因多余远程 Dockerfile frontend 解析超时，尚未开始 Go；保留原失败，仅去掉此非必要外部依赖后完成同源码回归。

同冻结源码构建正式 Agent。镜像、三节点预载、在线读取延迟及 PG Grow/Shrink/Regrow/自动策略仍须后续真实验证，不能由单元测试替代。SDK 使用原缓存和明确资源限额，不改宿主机网络或业务安全预算。
