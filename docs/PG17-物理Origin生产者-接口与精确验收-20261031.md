# PG17 物理 Origin 生产者组件交接（2026-10-31）

已实现三个独立新文件，默认无生产消费者；四个精确 U 根、18 子例 race 通过。物理观察三文件和其他代理的 native_test 没有修改。此组件只捕获原资源 Bootstrap 之前的物理组件，不证明整个 Guest 的历史、Root 未来不会漂移或完整 normal 上界。

生产 API 都没有请求 policy/path 参数：`CapturePhysicalKernelOrigin(ctx)`、`ObservePhysicalKernelOrigin(ctx)`、`ReplayPhysicalKernelOrigin(ctx)`。返回对象 `ReferenceSHA256()` 给出唯一 producer 规范文件的准确 SHA；摘要不认证自行构造的对象，调用者必须先成功读取原本地来源。

原固定 `/neonvm/runtime/dsga-physical-kernel.json` 与现 `dsga-resource.json` 必须 root 控制、ISO9660/只读，resource RuntimeDocument 的 SourceSHA/UID/incarnation 完整核验；policy 绑定整个 runtime 原文 SHA。新 kernel marker 是 `neonvm.dsga.physical_profile=kernel-v1`，重复/不支持值拒绝。当前 Controller/Runner 尚不生成这个 policy/marker，provision 也尚未调用 API。

policy 字段为 protocol_version=1、profile_id=`pg17-linux-6.12.26-physical-component-v1`、完整 kernel release、notes/artifact/config SHA、runtime_document_sha256。首 artifact/config/release 精确冻结到已复核构建；notes 来自实际观察且必须与原可信 policy 一致。它们是构建/启动源引用，不能仅靠 Guest 自报摘要认证整幅镜像。

Origin 字段为 v1、scope=`pre-bootstrap-physical-component-only`、vm_shrink_permit=false、一次随机 nonce、policy 原文 SHA、resource SourceSHA/runtime 原文 SHA、原 incarnation/Secret UID、Config/ExpectedBootstrap 和首次完整 PhysicalObservation。原 K/CPU/PID/kernel/boot/source 不得漂移，MOVABLE 可变部分只作当前核验，不改首次原文件。

创建使用同 StateDir resource flock：无 data/确认时要求原 state.json 不存在且真实 PG procs/threads 为空，再读内核；先 O_EXCL 写 data+fsync+dir，再 O_EXCL 写其准确 hash 确认+fsync+dir。新 marker/O_EXCL/当前空组不独立证明从 Guest 启动以来无旧工作负载，未来完整出生消费者必须另证，旧 state 无原 data 一律不能补新捕获。

已有 data 缺确认表示未完成/未知。普通 Capture/Observe 不自动补写；只有显式 Replay 在仍无资源 state、空组、原 source/current物理相符时同步同一 data、补同一摘要确认。部分/损坏/符号链接/非规范 producer 字节均保留并拒绝，不删文件、不重造 nonce。确认文件可见也不等于已经收到旧调用 fsync 成功 ACK；显式 Replay 即使已有确认也同步 data/确认/目录。组件没有底层资源写，取消不留下后台资源动作。

真正生产顺序仍待主执行接线：可信新 profile/marker+readonly ISO→建空受管组→组件 Capture/必要显式 Replay→Root Bootstrap→System/Native两阶段出生→所有R/filter/FS/I/恢复来源强制及封存。任何组件失败在显式 profile 内必须 fail closed，不得退 legacy；不能只因本组件成功就开放 PG 或五层 normal 降限。

尚缺：Controller/Runner immutable policy 发布、provision 顺序、原完整出生身份/特权写路径持续约束、旧 root charge 来源、U/R/S_reinit/F/I 与目标 MOVABLE 证明、真实 readonly ISO/数据盘重试 S、normal 真下降及服务恢复 E。原 PG SharedCost 的 startup_arrays_upper 可作为内部重建 floor 的真实来源；完整 reader 影子按单原 Root flock 的完整 A，而不是无条件扣 R。该预算算法尚未在此组件实现。
