# 普通 Pod 驱逐后的 Host 预算安全恢复

原 AutoscaleEnforcer 继续负责节点规划与伸缩准入；Host 账本是其持久状态，不另建分配器。
本改动只补普通 Pod 已由 Kubelet 终止、旧容器明细被清理后的恢复来源。PG、Guest、VM
内存执行及真实 normal 硬降限合同不变，不能把普通 Pod 的来源用于任何 VM Runner。

## 来源与信任边界

仅消费固定 kube-system 命名空间中由可信运维流程发布的不可变 ConfigMap；读取权限按
本轮精确名称授权。名称、SHA 和 Node ownerRef 都不是来源认证。实际权限负测发现
blockOwnerDeletion 本身不能证明发布者权限，因此不能靠该字段签发停止事实。

来源绑定原 Node UID、Host Lease UID、账本 Origin、原 Pod UID、完整 spec/status 摘要及
容器集合。节点采集必须覆盖真实 Kubelet runtime、完整 CRI 列表、cgroup/proc 视图，
保留每个采样错误并验证运行中 Pod 的正对照。缺数组、权限错误、截断、未知状态和只见
API Failed/404 均不授权释放。已清理的旧 CID 不伪造，也不以 RSS/常数替代运行事实。

来源证明同 UID 不可再次启动的过去终态；不另加短 TTL，也不因节点后来重启就撤销原
事实。捕获时的本地 boot 和 API Node 前后绑定必须一致。原来源 CM UID/内容摘要一经
退休意图固定，不随重试更换。读回不确定时沿原对象恢复，不能重新初始化账本。

## 执行和恢复顺序

1. 节点只读采集、编码和生产 Go 校验可并行准备；这些步骤不发布来源、不改预算。
2. 可信运维者发布来源并读回真实 CM UID 和内容摘要；SourceRef 只引用这个原对象。
3. 消费者实际就绪、当前原 Node/Pod/spec/status/Origin/placement 核验通过后，才绑定
   SourceRef。节点 owner 按原 Lease 选主和 fence、原 Pod 退休意图、Node CAS 执行。
4. CAS 前和结果确认时都重读原来源；确认原行及所有峰值已结清后，才移除 Pod 保护。
   失败、响应丢失或来源改变均保守停留，不把缺行或超时当成功。

普通来源使用独立退休记录 v2；旧 v1 和受管 VM 不产生新字段。v2 必须经过能重读来源的
接口，纯内存检查不能宣称闭合。写入 v2 后，旧 Scheduler 读者会安全拒绝这些未闭合
记录；不得为了回退镜像删除字段或 Unknown。需保留兼容读者完成正式退役及归档。

## 本阶段验证边界

新增来源的完整性、错误身份/来源拒绝、丢回复续接、历史 boot，以及直接受影响的
原 managed 退役和初始化调用方均纳入针对性组件回归。旧 managed fixture 的硬限、
Hold floor 和版本屏障按当前合同保持一致；不降低生产校验，也不冒称旧 v6 认证。
组件通过不代表集群实际结账、Compute SQL 或四项内存端到端通过。节点采集与真实 API
的 typed Go 哈希交叉、可信来源发布及实际 Node 回读必须另行保存实证。

大日志、原始事实与失败记录留在 118 /data/neon-k8s-pg17 和 /data/neon-build；Git 只提交
可复现源码与说明。PG17/PG18 复用此 Host 层，内核和 Guest 的安全降限须各自真实验证。
