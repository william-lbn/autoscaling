# 原生期限过期后的受限管理：Mac 阶段验收

日期：2026-10-29，Asia/Shanghai。沿用当前自有功能分支及冻结基线。本批解决原生过期后 Run 退出、正式管理入口随之失效的问题，是受控重开业务的必要前置；持久 rearm/重新开放尚未实现，PG17 整体保持未完成。

## 行为与不变量

Run 首次协商发现原生期限已过期时，保留当前 Session 和唯一串行管理 goroutine，进入受限等待。运行中续租观察到过期也进入同一状态；在本 Run 内，普通来源恢复或只读结果不能清除此状态。管理查询、原 Root 有界修复和原关闭恢复仍走原 Session/完整实例/选择摘要核验；其余 Begin、取消、旧开放/PG/资源/VM 重放及恢复开放全部拒绝。普通 Advance、自动策略与重放通道不会在已观察过期状态下继续派发，也不盲续租或自动 rearm。

管理请求可能排队至过期，因此业务入口在外层 WAL 写前额外查询原生期限；查询错误或坏回复不能继续派发。跨网络检查不是跨域原子租约，实际内核仍独立按单调期限关闭准入；本批不声称消除了检查与调用之间的所有时差。

回归发现原先精确零派发取消的 Finish 丢回复后，原取消已经进入历史，旧协商判断会额外取 PG 凭据。现只在没有任何预算/服务关闭/淘汰记录、完整历史全为零派发取消、当前 Active 也仍为零派发取消或空时允许本地读回；一般空闲状态不能获得该特例。后续新 Begin 在外层写前强制退出特例并协商原生期限，失败不能先接受新意图。已有预算/未知/派发步骤均不能降级。

## 实际验证与原失败

新增生产测试先在原实现复现启动过期导致 Run 直接退出，再验证启动过期、运行中续租过期、管理请求排队期间过期三模式；每模式状态查询仍可用，12 类业务/旧开放恢复拒绝，原 WAL/预算、门禁/Resize 请求次数和 deadline 不变。新生产组合执行一次真正本地取消，再启动第二次 Run 查询历史；后续 Begin 遇旧网关失败，确认新 WAL 未写入。

Mac race 按 package/test 去重 **13 顶层、64 条含父子记录，0 fail/skip**；含原管理串行/取消、实际 HTTP 失租、显式原重放、关闭通道及零派发取消四模式。完整自动 Grow→Shrink **167.24 秒**通过，生产正常 Finish/Host 结清，QMP peer 读回 1 GiB，扩缩各一次，未放宽采样间隔或领域安全条件。最终 vet、增量 lint 0 issues，33 个共享消费者仅编译通过。准确日志和源码 SHA256 见同名机器收据，父子记录不等于独立 E2E 次数。

原启动过期退出、Finish 丢回复后多取 PG 凭据及首轮两项 lint 失败日志完整保留。修复后仅复验新增、修改及受影响边界；最后的本地取消历史修复不改变有完整预算的自动组合分支。Kube、PG、Root、QMP 是明确协议 peer；本批没有修改或重编 PG/Rust，没有新真实 PG 或 Linux 执行。
